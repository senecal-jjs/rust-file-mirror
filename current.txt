. Resume-checking has to happen before the normal scan → reconcile → apply flow, 
not inside it. It's fundamentally "finish what a previous session left half-done," 
not part of this session's diff. I'd make it an explicit pass at the start of a sync: 
read all uploads rows, and for each, compare the file's current hash against the hash 
recorded when the upload started (captured via the same hash_stable call upload() 
already does). Match → resume, skipping already-uploaded parts. Mismatch or file gone → 
the stored upload_id is stale, so abort_multipart_upload it and delete the row, letting 
the normal reconcile logic pick the file up fresh if it still needs syncing.
